# 0.1.2 — 2026-10-01

## Added

- **`coastalBufferKm`** on `geonames_reverse_geocode` (0–50, default 0) — when no country contains the point, matches the nearest country within that many km, for harbor and shoreline fixes; a buffered match carries `country.distanceInKm`, at no extra credit ([#7](https://github.com/cyanheads/geonames-mcp-server/issues/7)).
- **Alpha-3 and numeric country codes** (`USA`, `840`) in the `countries` filters of `geonames_search_places` and `geonames_find_postal_codes`, sent to GeoNames as alpha-2 from a bundled 250-country table; a well-formed code no country has fails as `unknown_country_code` ([#8](https://github.com/cyanheads/geonames-mcp-server/issues/8)).
- **`sameAsAdministrative`** on `geonames_get_children` — flags, with a notice, a `tourism` or `dependency` answer that equals the administrative children, GeoNames' fallback when the feature has no such tree; the check costs 1 more credit unless the administrative list is cached ([#5](https://github.com/cyanheads/geonames-mcp-server/issues/5)).
- **Public hosted endpoint** — `server.json` lists `https://geonames.caseyjhand.com/mcp` as a streamable-http remote, and the README documents the hosted instance.

## Fixed

- **`hierarchy: "geography"`** on `geonames_get_children` now fails validation: GeoNames holds no geography tree and answered with the administrative children ([#5](https://github.com/cyanheads/geonames-mcp-server/issues/5)).
- **`feature_filter_mismatch`** — `geonames_search_places` and `geonames_reverse_geocode` reject, before the request, a code whose class is not in `featureClasses` or a listed class with no code; GeoNames intersects the two lists, so those entries matched nothing ([#6](https://github.com/cyanheads/geonames-mcp-server/issues/6)).
- **`cities` beside a non-P filter** in `geonames_search_places` — a class other than P or a code outside class P now fails as `feature_filter_mismatch` instead of returning an empty page ([#9](https://github.com/cyanheads/geonames-mcp-server/issues/9)).
- **Offshore `dstOffsetInHours`** in `geonames_reverse_geocode` reports the standard offset: without a `timezoneId`, GeoNames' `dstOffset: 0` placeholder is replaced by `rawOffset` ([#4](https://github.com/cyanheads/geonames-mcp-server/issues/4)).
- **Kosovo's `isoNumeric`** — GeoNames' `"0"` placeholder is dropped, so `geonames_get_countries` returns Kosovo with no numeric code and lists `000` in `notFound` ([#10](https://github.com/cyanheads/geonames-mcp-server/issues/10)).
