# 0.1.3 — 2026-10-18

## Added

- **`adminCode1`–`adminCode4`** on `geonames_search_places` — exact admin-division filters from the `adminLevels[].code` values of `geonames_get_place` and `geonames_reverse_geocode`; they need exactly one country in `countries` (and `adminCode1` for levels 2–4), else `admin_code_unscoped` ([#22](https://github.com/cyanheads/geonames-mcp-server/issues/22)).
- **`offset`** and **`nextOffset`** on `geonames_find_postal_codes` modes `code` and `place_name` — page past the 100-row cap, up to offset 5000; `nearby` does not page and rejects an offset above 0 as `mode_fields_mismatch` ([#21](https://github.com/cyanheads/geonames-mcp-server/issues/21)).

## Changed

- **Over-cap limits are clamped** — `limit` on the five list tools and `nearbyLimit` on `geonames_reverse_geocode` accept up to 1,000 and are held to the tool's cap; `cap` reports the applied value and the notice names the clamp when rows remain ([#15](https://github.com/cyanheads/geonames-mcp-server/issues/15)).
- **Dated UTC offsets** (`gmtOffsetInHours`, `dstOffsetInHours`) in `geonames_reverse_geocode` and `geonames_get_place` are derived from the IANA zone id; GeoNames' deprecated `gmtOffset`/`dstOffset` apply only where the runtime does not know the zone ([#11](https://github.com/cyanheads/geonames-mcp-server/issues/11)).
- **Argument repair** from `@cyanheads/mcp-ts-core` 0.13.15: a `null` for an optional argument counts as omitted, so its default applies, and `lat` and `lng` sent as numeric strings are accepted. `limit`, `offset`, `nearbyLimit`, `radiusKm`, and `coastalBufferKm` still refuse numeric strings (cyanheads/mcp-ts-core#725).

## Fixed

- **`truncated`** on `geonames_find_postal_codes` and the nearby lookups of `geonames_reverse_geocode` is true only when a row past the limit exists; a page that exactly fills its limit no longer reports truncation ([#18](https://github.com/cyanheads/geonames-mcp-server/issues/18)).
- **`orderBy: "relevance"`** on `geonames_search_places` is sent to GeoNames, where it orders `name_prefix` searches differently from the default ([#17](https://github.com/cyanheads/geonames-mcp-server/issues/17)).
- **`sunrise` and `sunset`** in `geonames_reverse_geocode` fall on `localTime`'s date, where GeoNames' pair could belong to the previous or next local day ([#19](https://github.com/cyanheads/geonames-mcp-server/issues/19)).
- **`countries`** — an alpha-2 code GeoNames files nothing under (`EL`, `EU`) fails as `unknown_country_code` instead of being dropped beside valid codes ([#14](https://github.com/cyanheads/geonames-mcp-server/issues/14)); `FL` is read as Liechtenstein.
- **Dependent territories** that GeoNames returns under a listed country are named in the notice of `geonames_search_places` and `geonames_find_postal_codes`, each row keeping its own `countryCode` ([#20](https://github.com/cyanheads/geonames-mcp-server/issues/20)).
- **Monaco's first-level division** (code `00`, geonameId 3319178) is kept; a `00` with no admin id is still dropped as GeoNames' placeholder ([#24](https://github.com/cyanheads/geonames-mcp-server/issues/24)).
- **Enrichment text** — `effectiveQuery` and notices carry the strings as received in `structuredContent`; the Markdown escaping applies only to `content[]` ([#16](https://github.com/cyanheads/geonames-mcp-server/issues/16)).
- **Markdown in names** — `*`, `` ` ``, `~`, and non-intraword `_` in GeoNames text are escaped in `content[]` ([#23](https://github.com/cyanheads/geonames-mcp-server/issues/23)).
- **Cancelled callers** — an aborted caller no longer cancels the upstream request that identical in-flight calls share, and a cancelled waiter rejects at once with its own reason ([#12](https://github.com/cyanheads/geonames-mcp-server/issues/12)).
- **Input descriptions** offer only the forms the advertised schema accepts (lists, canonical case, `geonameId` as a digit string); the other forms are still tolerated ([#25](https://github.com/cyanheads/geonames-mcp-server/issues/25)).
