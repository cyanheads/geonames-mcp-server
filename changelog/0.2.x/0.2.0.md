# 0.2.0 — 2026-10-29

## Added

- **`geonames-guide` agent skill** — served as `skill://geonames-guide/SKILL.md` (listed by `resources/list`, template `skill://{+path}`) through `createApp({ skills: 'skills' })`; it covers postal-to-gazetteer crossings, population gates, searching inside a division, and the timezone at a coordinate. The server `instructions` point to it, and `skills/` ships in the npm package and the Docker image.
- **Root `plugin.json` and `mcp.json`** — the Agent Plugins manifest pair, with the unscoped server name and an `npx -y @cyanheads/geonames-mcp-server` stdio entry.

## Changed

- **Full-page nearby notices** name the route to the rest ([#26](https://github.com/cyanheads/geonames-mcp-server/issues/26)): `geonames_reverse_geocode` prints the `geonames_search_places` call, with a `boundingBox` enclosing the radius, and says the search lists rows by relevance, so keep those within `radiusKm`; `geonames_find_postal_codes` mode `nearby` says it does not page and a call from another point returns that point's nearest 100.
- **`geonames_get_place` timezone notice** — a record with a `timezone` and no `countryCode` carries a `notice` on both surfaces saying the zone is the one GeoNames associates with the record, with the `geonames_reverse_geocode` call for the time at its coordinates ([#30](https://github.com/cyanheads/geonames-mcp-server/issues/30)). The `timezone` field description says the same for every record.
- **Tool descriptions** — `geonames_get_children` routes to `geonames_search_places` by country and admin codes for other feature types, for a parent with no children, and for one with more children than it returns; `adminCode1`–`adminCode3` on postal rows are marked as postal-dataset codes that `geonames_search_places` does not filter on; `postalCodes` on `geonames_get_place` is marked as possibly shorter than `geonames_find_postal_codes`; `cities` notes that PPLX sections with their own population pass.
- **`.mcpb` bundle** leaves out `src/`, `docs/`, `changelog/`, `CLAUDE.md`, `AGENTS.md`, the plugin manifests, and other repo-only root paths.

## Fixed

- **`nameContains` with no letter or digit** — punctuation, symbols, emoji, or combining marks or invisible characters alone — fails as `name_contains_unsearchable` before any GeoNames request on `geonames_get_countries`, `geonames_get_children`, and `geonames_list_reference`; it used to match every row ([#29](https://github.com/cyanheads/geonames-mcp-server/issues/29)).
- **URLs in `content[]`** print as written, with no bracketed `https[:]//` or `www[.]`, so a CommonMark parse reads back the `structuredContent` value ([#28](https://github.com/cyanheads/geonames-mcp-server/issues/28)).
- **`structuredContent.error.message`** for `upstream_rejected_parameter` carries the GeoNames text without Markdown escapes; the `Error:` line of `content[]` is escaped by the framework (cyanheads/mcp-ts-core#760) ([#28](https://github.com/cyanheads/geonames-mcp-server/issues/28)).
